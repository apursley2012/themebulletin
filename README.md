<a id="project-overview"></a>

<details open>
<summary><h2><strong>Project Overview 🔎</strong></h2></summary>





**Theme Bulletin** is a searchable catalog for a collection of standalone website themes. Instead of reducing dozens of distinct designs to repository links, it gives each theme a visible identity through categories, short descriptions, home-page previews, live demos, repository links, and individual documentation.

I created the project to make a large design collection practical to explore. Visitors can compare visual directions, narrow the catalog by category, open a theme directly, and move from a preview to the full standalone repository without needing to know the theme name in advance. The bulletin acts as the directory, while each theme remains an independent site that can be customized and published on its own.

The README follows that same catalog model. It documents how Theme Bulletin is organized, explains the relationship between the collection and individual repositories, and includes a categorized theme directory whose short descriptions are kept identical to the descriptions at the top of the individual theme READMEs.

</details>

<a id="purpose"></a>

<details open>
<summary><h3><strong>Purpose 🎯</strong></h3></summary>




I created **Theme Bulletin** because a growing collection of standalone website themes becomes difficult to browse once it is reduced to a long list of repository links. The project gives the collection a central catalog where each theme can be searched, filtered by category, previewed, checked for availability, and opened as a live site or repository. Its purpose is to make the themes easy to discover and compare while allowing every design to remain an independent, reusable project with its own code and documentation.
</details>

<a id="design-style-and-inspiration"></a>

<details open>
<summary><h3><strong>Design Style and Inspiration 🎨</strong></h3></summary>



Theme Bulletin is built around a literal bulletin-board idea rather than a conventional theme gallery. Cork tones create the shared surface, while yellow, blue, pink, green, and cream paper colors distinguish theme notes and supporting information. Dark ink, green controls, and orange accents keep the collection navigable even when many notes are visible at once. The physical-board metaphor gives the collection its personality, but search, filtering, status, previews, and links remain the functional center.

</details>

<a id="github-pages-deployment"></a>

<details open>
<summary><h3><strong>GitHub Pages Deployment 🌐</strong></h3></summary>



For the static/public portion, keep `index.html` at the repository root, use relative asset paths, then enable **Settings → Pages → Deploy from a branch → main → / (root)**. Projects that include Python, Node, MongoDB, authentication, browser automation, or another server runtime still need an appropriate backend host for those server-dependent features.

</details>

<a id="themes"></a>

<details open>
<summary><h2><strong>Themes 🧷</strong></h2></summary>

Theme Bulletin brings together a growing collection of standalone website themes that explore very different approaches to presenting the same kinds of professional content. Some are built around developer workspaces, terminals, operating systems, and technical dashboards; others lean into retro computing, arcade interfaces, celestial environments, handcrafted creative layouts, or darker magical themes. Each theme has its own visual language, page structure, interaction patterns, component choices, and personality while still supporting the practical content a professional site needs.

I organized the collection into broad categories to make those differences easier to explore without forcing every design into an overly narrow label. A visitor can start with a category that fits the type of experience they want, compare the individual themes visually, then open the complete standalone project for the design that interests them. Each theme remains independent from Theme Bulletin, so it can be customized, maintained, and deployed without depending on the catalog itself.

<details open>
<summary><h2><strong>Categories 🗂️</strong></h2></summary>

<a id="collection-relationship"></a>

<details open>
<summary><h2><strong>Collection Relationship 🗞️</strong></h2></summary>



Theme Bulletin is the directory, not the source repository for every theme. The gallery stores the metadata needed to browse the collection and links outward to each standalone theme repository. That separation means one theme can be updated, repaired, or documented without forcing the entire collection into one shared build.

Unavailable themes are kept visible when that status is useful. Instead of fabricating a preview or silently removing the entry, Theme Bulletin can mark a theme for manual review until its source files are restored.

</details>

<a id="customization-guide"></a>

<details open>
<summary><h2><strong>Customization Guide 🎨</strong></h2></summary>



The safest way to customize or extend **Theme Bulletin** is to preserve its existing workflow first, then change one layer at a time. Update project content and data in the files that already own that information, keep visual changes inside the existing style system, and test every page that shares the changed component or data source. New features should solve a problem that belongs to this project instead of copying a feature from an unrelated application.

For visual changes, update the documented palette intentionally and re-check contrast, responsive spacing, screenshots, and any state colors that depend on the same variables. For data or logic changes, test both the normal path and empty/error/edge cases before publishing.

</details>

<a id="accessibility-and-browser-compatibility"></a>

<details open>
<summary><h2><strong>Accessibility and Browser Compatibility ♿</strong></h2></summary>



The public interface should remain keyboard-navigable, readable at common mobile and desktop widths, and usable without relying on color alone to communicate state. Form controls should keep visible labels or accessible names, images should use meaningful `alt` text, focus indicators should remain visible, and decorative animation should respect reduced-motion preferences when motion is present. Browser compatibility should be checked in current Safari, Chrome, Firefox, and Edge where practical.

</details>

<a id="repository-relationship"></a>

<details open>
<summary><h2><strong>Repository Relationship 🔗</strong></h2></summary>



**Theme Bulletin** is documented as its own project. Supporting case studies, articles, source history, static presentation layers, or backend/runtime folders are parts of this repository only when they help explain or run this project. They should not be described as separate replacement projects.

Where this repository contains both a static GitHub Pages layer and source that requires another runtime, the two are related but not interchangeable: the static layer provides the public experience that can run in a browser, while the source/runtime layer preserves functionality that GitHub Pages cannot execute directly.

</details>
